## 问题陈述（用户原声）

1. 手机浏览器里，remobi 内置的 `− + ?` 字体控件（`#wt-font-controls`，fixed 右上角）挡住 herdr TUI 的 "switch" 开关，无法点击。
2. 系统是否支持 PWA？——已支持（manifest + apple meta + icons），深化（SW）被显式否决。
3. 点终端屏幕即唤起软键盘并触发全屏重排；用户要求 moshi 式体验：由用户决定什么时候允许键盘。

## Vision

### 10x Check
moshi 的完整形态是 agent-aware 遥控器：知道 herdr workspace/tab 状态、锁屏推送 blocked 事件、一键跳进等待中的 agent。本次只取其中两块砖——键盘主权与终端内容零遮挡——但方向对准这个形态。

### 核心机制（T-A 决策：spike 先行）
- **首选 `inputmode="none"`**：为「不弹虚拟键盘」而生的属性，textarea 保持可编辑，**实体键盘输入不受影响**（iPad 场景直接成立）。
- **readonly 为兜底**：iOS Safari 若不支持 inputmode="none" 则回退（readonly 会一并阻断实体键盘，届时 iPad hardware keyboard 需另案评估）。
- 按钮发送按键走 `term.input(data, true)`（`src/util/terminal.ts:4-6`），两条机制下均绕开 textarea，不受影响。
- **Spike（增量 0，阻塞后续）**：四项探针——①iPad 实体键盘在 inputmode=none/readonly 下是否可输入；②中文/日文 IME 组合中关闭键盘的行为（commit/丢弃，写成 pass/fail 标准）；③touchend→合成 mousedown 的焦点竞态（toggle 的 focus 是否被按钮抢走）；④系统手势收起键盘的事件信号。探针通过才写状态机。

## 增量划分

### 增量 0：机制 Spike（阻塞项，~30min CC）
- 最小 HTML 探针页 + xterm 实例，真机（iOS Safari / Android Chrome / iPad+实体键盘）验证上述四项。
- 产出：机制选型定案（inputmode=none 或 readonly）+ IME pass/fail 验收标准文本 + 焦点竞态结论（决定 toggle 的 focus 时序实现）。

### 增量 1：控件移位 + safe-area（独立、低风险，可先发）
- **− / + / ? 从悬浮 `#wt-font-controls` 移入 drawer**，成为默认 `ControlButton` 项（fontIncrease/fontDecrease/help 三个 `type: 'send'` 之外的内部 action 或自定义 action 类型，实现卡定）；`#wt-font-controls` DOM 与 CSS 删除。
- Help 入口随之进入 drawer，不再依赖悬浮按钮（Codex #8 闭环）。
- `scrollButtons` 进 config schema：仅 `enabled`（默认 true）；位置配置后置。
- safe-area 补齐 top/left/right inset（bottom 已存在，不重做），覆盖 `#wt-scroll-buttons` 与 `.wt-floating-group` top/right 方位类。
- 顺手 chore：修正 `src/util/tap.ts:20` "13 call sites" 过时注释为 11。

### 增量 2：键盘主权（依赖增量 0 的 spike 结论）
- `mobile.keyboardMode: 'auto' | 'manual'`，默认 `'auto'`（向后兼容）。
- **三信号状态模型（T-B）**：
  - `inputPermission`（输入许可，唯一事实源）：manual 进入时 = false → textarea 恒不可输入（inputmode=none 或 readonly），与视口测量无关。
  - `textareaFocus`（焦点信号）：focus/blur 事件跟踪。
  - `keyboardVisible`（可见性，`isKeyboardOpen()` 启发式）：**只驱动指示器，不参与任何状态迁移**。
  - 系统手势收起键盘 → 许可仍为用户所设状态；manual 下许可=false 时无需「重新上锁」（锁从未松开），消除 Codex #3 的永久解锁路径。
- `keyboard-toggle` action：
  - 默认挂载 toolbar row2 最右（D4），可配置挪走；`wt-kb-open` 横屏隐藏 row2 规则对其豁免（F1）。
  - 共享键盘状态控制器（T-E #4）：单一 controller + 订阅，按钮激活态/置灰/多实例一致；ActionRegistry 不直接碰 DOM。
  - 焦点时序按 spike ③ 结论实现（T-E #2）；快速连点 ~300ms 防抖。
  - 配置自锁防护（T-E #5）：manual 模式下若用户自定义按钮数组不含 keyboard-toggle，drawer 末尾自动追加一个键盘项作为逃生入口。
  - fail-loud 用户可见（T-E #6）：机制不可用（textarea 缺失/探针机制均失败）→ 按钮显示错误态 + reconnect 式 overlay 提示，不止 console.error；禁止静默退回 auto。
  - IME：按增量 0 定案的 pass/fail 标准验收，真机矩阵含中文/日文用例。
- 真机矩阵（PR 标 ready 前完成，merge=自动发 npm 无缓冲带）：iOS Safari / Android Chrome × manual 全迁移 + 横屏 ⌨ 可见性 + IME + iPad 实体键盘 + combo-picker + 粘贴路径。
