## 问题陈述（用户原声）

1. 手机浏览器里，remobi 内置的 `− + ?` 字体控件（`#wt-font-controls`，fixed 右上角）挡住 herdr TUI 的 "switch" 开关，无法点击。
2. 系统是否支持 PWA？——已支持（manifest + apple meta + icons），深化（SW）被显式否决。
3. 点终端屏幕即唤起软键盘并触发全屏重排；用户要求 moshi 式体验：由用户决定什么时候允许键盘。

## Vision

### 10x Check
moshi 的完整形态是 agent-aware 遥控器：知道 herdr workspace/tab 状态、锁屏推送 blocked 事件、一键跳进等待中的 agent。本次只取其中两块砖——键盘主权与终端内容零遮挡——但方向对准这个形态。

### 核心机制（V3 决议：spike 定单一机制，不做运行时回退）
- **候选 `inputmode="none"`**：为「不弹虚拟键盘」而生，textarea 保持可编辑，实体键盘输入不受影响（iPad 场景成立）。
- **兜底 `readonly`**：iOS Safari 若验证不通过则**全平台**回退 readonly（iPad 实体键盘受限写入文档，不运行时探测——规范对 inputmode 只有 "should"，不存在可靠程序化信号，运行时探测会重新引入被 T-B 否决的启发式漏判路径）。
- 按钮发送按键走 `term.input(data, true)`（`src/util/terminal.ts:4-6`），两条机制下均绕开 textarea。
- **Spike（增量 0，阻塞后续），五项探针**：①iPad 实体键盘在 inputmode=none/readonly 下是否可输入；②中文/日文 IME 组合中关闭键盘的行为（commit/丢弃，写成 pass/fail 标准）；③touchend→合成 mousedown 的焦点竞态（`src/util/tap.ts:33` 不 preventDefault，toggle 的 focus 是否被按钮抢走）；④系统手势收起键盘的事件信号；⑤**键盘已打开时执行锁定**（permission=true+focused+visible → 抑制）：仅改属性是否足够，还是必须先 `blur()` 再改属性——顺序用证据定案。
- 产出：单一机制定案 + IME pass/fail 验收标准 + 锁定/解锁时序结论。

### 增量 2：键盘主权（第二个 minor，依赖增量 0 结论）
- `mobile.keyboardMode: 'auto' | 'manual'`，默认 `'auto'`。
- **XTerminal 语义扩展（Eng-2）**：`setKeyboardSuppressed(suppressed)` + `onFocusChange(cb)`；机制（inputmode/readonly）由 client-entry 按 spike 结论单点实现。
- **三信号状态模型（T-B）**：`inputPermission` 唯一事实源（manual 下 = false 时 textarea 恒不可输入）；`textareaFocus` 事件跟踪；`keyboardVisible` 只驱动指示器、不参与任何迁移。系统手势收键盘 → permission 不变（无「重新上锁」迁移，锁从未松开）。
- **keyboard-toggle**：
  - 默认挂 toolbar row2 最右（D4）；`wt-kb-open` 横屏隐藏 row2 规则对其豁免（F1）。
  - **auto 模式语义（V1）**：瞬时控制（focus/blur），无 permission 状态；指示器 auto 下跟 `keyboardVisible`，manual 下跟 `inputPermission`。
  - 共享状态控制器（T-E#4）：单一 controller + 订阅；ActionRegistry 不碰 DOM。
  - 时序按 spike ③⑤ 结论；连点 ~300ms 防抖。
  - **逃生入口（V2）**：init 渲染前检查解析后按钮全集，manual 且无 keyboard-toggle → 注入 **toolbar row2**（toolbar 保证渲染；drawer 可被整体替换且 drawer-toggle 可删，Codex 第 2 轮 #2）；config-resolve 保持纯函数。
  - **row2 窄屏修复（V2 附带）**：row2 加 `min-width`/`overflow-x: auto`，320px 下按钮 ≥44px 或可横滑，写入验收。
  - fail-loud 用户可见（T-E#6）：机制不可用 → 按钮错误态 + reconnect 式 overlay；禁止静默退回 auto。
  - IME：按 spike 定案的 pass/fail 标准验收。
- **Playwright 契约测试（V6#8）**：断言真实 textarea 的 suppressed 属性、focus/blur 事件、按钮发送产生 WS input payload——`client-entry.ts` 被覆盖率排除（`vitest.config.ts:49`），mock 测试不构成接线证据。
- 真机矩阵（PR ready 前硬闸门）：iOS Safari / Android Chrome × manual 全迁移 + auto 瞬时控制 + 系统手势后锁定保持 + 横屏 ⌨ 可见 + IME + iPad 实体键盘 + combo-picker + 粘贴路径。

## 风险与验证盲区

- iOS Safari 对 inputmode="none" 支持历史有疑点——增量 0 spike 定案，readonly 兜底。
- 软键盘全链路无法 happy-dom 验证——Playwright 契约测试（属性/事件/payload 层）+ 真机矩阵（OS 键盘层）双闸门。
- 默认值变化两处（字体控件移除、scrollButtons 默认关闭）——changelog 写明；功能均可配置恢复。
