## 背景三段式

1. 方案已定：手机浏览器采集音频 → **直连**火山 wss（不经过 remobi 服务端）→ 识别文本在浏览器本地注入终端。服务端只有两个 header + 一个 worklet 静态路由 + config schema 的改动。
2. 直连的前提是**query 参数鉴权**（浏览器 WebSocket 不能自定义握手 header；火山官方前端 SDK `byted-ailab-speech-sdk` 文档称前端走 query 鉴权，但「bigmodel 服务是否覆盖」未经实证）。
3. no-go 的退路已留：转服务端代理方案重评（设计文档 NOT in scope 节有记录）。no-go 也是有效产出，不要硬凑 go。

## 开工前必须向用户拿到的输入

- 火山引擎语音服务的 **App Key 与 Access Key**（控制台「豆包语音·大模型流式语音识别」开通后签发），resourceId 默认 `volc.bigasr.sauc.duration`（以控制台/文档为准，spike 中确认）。
- **密钥禁止进 git**：用环境变量（`VOLC_APP_KEY` / `VOLC_ACCESS_KEY`）或未跟踪的本地文件读取，探针脚本内不得出现明文，fixture/日志/备忘里不得包含密钥与完整带参 URL（打 origin 即可）。
- 真机验证步骤需要用户在手机上配合（见任务 5），脚本与页面由你准备好。

## 任务清单

1. **侦察 query 鉴权参数名**（先行，决定探针怎么连）：
   - 读 `byted-ailab-speech-sdk` 的源码/demo（npm registry tarball 或其 GitHub 仓库），找出它对各服务使用的 query 参数名（文档原话「不同的服务需要的 auth 参数不同，可查看具体服务 demo」）。
   - 对照火山文档 6561/1354869（大模型流式 ASR）与社区 demo，列出候选参数组合，逐一试。握手 header 鉴权（X-Api-App-Key/X-Api-Access-Key）作为对照组也试一次（Node 可以设 header，用来区分「密钥错」与「query 方式不支持」）。
2. **Node 探针脚本** `spikes/asr/probe-auth.ts`（tsx 直跑，ws 已在仓 dependencies）：
   - 连接 `wss://openspeech.bytedance.com/api/v3/sauc/bigmodel?<候选query>`，记录握手成功/失败/断开码。
   - 成功后：按 SAUC 协议发 full client request（16kHz/16bit/mono PCM），再发程序生成的 PCM 音频包（正弦波或静音即可，目的是验证链路不是识别质量），接收并 **hex dump 全部收发帧**到 `tests/fixtures/asr/`（进 git，供增量 1 的 golden bytes 测试）。
   - 负包结束：发结束包（见任务 3 的 variant 确认），等 final 或超时，记录时序。
3. **帧格式备忘** `spikes/asr/PROTOCOL-NOTES.md`（完成后挪进 `docs/sessions/` 或 fixture 目录）：
   - header 各 nibble 实值（version/header-size/message-type/flags/serialization/compression）；
   - full client request 的 JSON 结构实样（脱敏）；
   - **结束包 variant 锁死**：flags `0b0010`（无序列最后包）vs `0b0011`（带序列最后包），payload offset 差异——用实帧定案（Codex 二轮 #8 明确要求）；
   - 三类错误的实际表现：握手拒绝（Node 能拿到状态码，浏览器拿不到——记录两侧差异）、协议错误帧 0xF、业务错误帧 0x9（含 X-Tt-Logid 是否在握手后可见）。
4. **opus 附带探针**：full client request 的 audio format 改 `opus`（其它不变），确认是否接受——若接受，增量 1 可重评 MediaRecorder 路径（设计文档 增量 0 节第 4 条）。
5. **浏览器探针页** `spikes/asr/probe.html`（单文件，给用户真机跑）：
   - `new AudioContext({ sampleRate: 16000 })` 的实际 `sampleRate` 输出（决定是否要 pcm.ts 线性抽取回退）；
   - AudioWorklet `addModule` 可用性；`getUserMedia` 在当前环境（Safari 标签页 vs 主屏 PWA）可用性；
   - 中断信号观察：来电/锁屏/切后台时 `track.onended`/`onmute`/`AudioContext.statechange`/`visibilitychange` 哪个触发（页面打日志，用户照着步骤操作）；
   - 给用户的一页操作步骤写进结果文档。
6. **go/no-go 结论**写入 `docs/sessions/260819-<HHMM>-asr-spike-results.md`：每项验收 ✅/❌ + 证据（日志摘录、fixture 路径）、结论、对增量 1 的影响（含 opus/采样率/尾包 variant 结论）。
