# NO-GO — 服务端帧差分重建 herdr scrollback：突发输出在源头丢失，不可行

- 任务卡：`docs/sessions/260821-1053-scroll/card-inc2-spike-scrollback.md`；探针：`spikes/scrollback/`（可重跑，见其 README；文内 `*.json` 指运行后生成于 `/tmp/spike-scrollback-captures/` 的 artifact，关键数字已摘录本文）
- 环境：herdr 0.7.5，独立 session `spike-scrollback`（node-pty 80×24 → `@xterm/headless` mirror，与 `src/session.ts:102` 同款 `scrollback: 5000`），全程未触碰用户 default/w15 会话
- **结论：NO-GO**。增量 2 的 GO 判据（≥10 分钟真实 agent 输出一致率 ≥95% 且零错误插入）无法满足，建议走降级方案 B（翻页式滚动）。

## 一、alternate screen 证据（确认）

原始 PTY 流中 `\x1b[?1049h` 出现 1 次、`\x1b[?1049l` 0 次（herdr 启动即进 alternate buffer，运行期不退出），并开启 `\x1b[?1002h` `\x1b[?1003h` `\x1b[?1006h` 鼠标编码；mirror 的 `buffer.active.type === 'alternate'`。alternate buffer 无 scrollback，滚出的内容只能被动重建——设计前提成立（`seq5000.json` 的 `altScreen`）。

## 二、seq 1 5000 确定性判据：FAIL（决定性）

判据：5000 行严格连续递增数字完整重建、零非数字插入。实测（`seq5000.json`）：**仅重建 1 行数字（4980）**。整个突发期间 herdr 只渲染约 2 个中间态——pane 内容一帧跳到 ≈1701 行处、再跳到 ≈4980，中间行从未进入 PTY 输出流。差分器全程 2 次滚动、7/9 变化帧对不齐被保守跳过，零 chrome 泄漏、零伪造。

归因是机制而非探针缺陷：探针帧粒度 = 每个 PTY chunk，已细于 herdr 的重绘粒度；合并发生在 herdr 渲染循环内部，渲染 tick 之间滚过屏幕的行在源头就没被画出，下游任何 diff 都无法恢复从未上线的信息。

## 三、粒度边界

| 场景 | 每渲染 tick 位移 | 捕获率 |
|---|---|---|
| paced 2000 行（10ms/行，模拟流式输出） | 1~2 行 | **1980/2000（99.0%）**，1530 次滚动，跳帧 70/1600，零错误插入 |
| 单次 burst 20 行 | ≈20 行 | 0/20 |
| 单次 burst 60 行 | ≫高度 | 1/60 |
| 单次 burst 200 行 | ≫高度 | 1/200 |

内容区 22 行、`minK=4`，理论上每 tick 位移 ≤18 行才可能对齐，实测悬崖更陡（`granularity.json`）。**捕获率由内容生产速率决定**：流式近全捕获，命令级突发（`seq`/`cat`/构建/测试输出）近全丢失。

## 四、干扰场景逐项（tab 切换 / resize / pane split / 全屏 TUI）

每场景后跑 15 行 paced marker 块（M1~M7），核对重建数、顺序、chrome 泄漏、帧成员校验（每条非 marker 历史行必须出现在某一帧的内容区域内，否则计伪造嫌疑）：

| 场景 | marker 重建 | 结论 |
|---|---|---|
| M1 基线 | 18/15 | 正常（多出 1 行为块间合法残留） |
| M2 tab 新建+切走+切回 | 8/15 | 切换期漏，切回后恢复 |
| M3 resize 100×30 | 15/15 | 尺寸变化重置基线；掩码是新视口子集，恢复后可对齐 |
| M4 resize 回 80×24 | 1/15 | 回缩 reflow 断裂期全漏（漏，非错插） |
| M5 pane split right | 15/15 | 布局变化后恢复（对侧空 pane 不干扰掩码） |
| M6 关闭 split | 16/15 | 恢复正常 |
| M7 退出 less 后 | 0/15 | 全屏 TUI 退出整屏还原，断裂期全漏 |

汇总（`interference.json`）：scrolls=107，跳帧 115/222（51.8%），resets=2（两次 resize）；**orderOk=true、chrome 泄漏 0、帧成员校验 unexplained=0（零伪造）**。符合保守原则——宁可漏、绝不错插，但漏得不少。

## 五、真实负载统计（≥5 分钟持续滚屏）

`find / -type f 2>/dev/null | head -3000` 连续循环 302 s、309 轮、共约 92.7 万行（`realload.json`）：重建 988 行（**0.11%**）；滚动事件 882；跳帧 3228/4110（78.5%）；轮完成标记捕获 0/309；chrome 泄漏 0；帧成员校验 unexplained=0（零伪造）。burst 型持续负载几乎全丢，与第二节机制一致。

## 六、已知误判/丢失场景清单

1. **突发输出**（≥20 行/渲染 tick）：源头合并重绘，全丢（决定性）。
2. 全屏 TUI 进出（less/vim）：整屏替换，断裂期全漏。
3. resize（尤其回缩 reflow）：基线重置 + 断裂期全漏。
4. tab 切换 / pane 开关：布局重绘期漏，恢复后正常。
5. chrome 变化（sidebar 选中态、tab 条、状态栏计时）：区域掩码 r1..r22 × c25..c78 多次运行稳定复现，未观察到 chrome 混入历史。
6. 校准依赖：区域/guard 需要内容丰富的滚动窗口被动学习；空屏/静态屏会给假证据。
7. 实现脆弱点：行首 pane 边框 `│` 跨行不完全对齐，需剥离。

零「错误插入」类误判：全场景 chrome 泄漏 0、伪造嫌疑 0、顺序保持——失败模式全部是漏。

## 七、NO-GO：没过的判据

- **GO 判据「≥10 分钟一致率 ≥95%」**：真实负载捕获率 0.11%，且随输出节奏在 99% 与 ~0% 间悬崖波动——任何含命令突发的会话必跌破阈值。瓶颈不在对齐算法，在 herdr 渲染合并导致的信息源头丢失，无算法可补救。
- **任务卡硬判据「seq 1 5000 严格连续」**：1/5000，FAIL。
- 唯一满足的是「零错误插入」，但保守原则的代价就是高丢失率，两者在本信道上不可兼得。

## 八、建议

按设计文档降级到**方案 B：翻页式滚动**。若未来 herdr 提供历史导出 API（事件流或 pane buffer 查询），增量 2 的服务端影子历史可免于此信道限制，届时可重开 spike。
